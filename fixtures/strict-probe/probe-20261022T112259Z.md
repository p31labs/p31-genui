# Strict-enforcement probe — 20261022T112259Z

A strict schema with a SINGLE-VALUE enum, and a prompt that invites a
DIFFERENT value. If the strict output carries the invited value, the
route is not constraining the decoder. The no-schema control shows
what the model wanted to say.

```
=== STRICT-ENFORCEMENT PROBE ===
provider=kilo model=poolside/laguna-s-2.1:free key=file:/home/p31/.local/share/opencode/auth.json#kilo.key

  schema: variant is a SINGLE-VALUE enum ["danger"]
  prompt: Emit a Badge with variant "success" and label "Active". Reply with JSON only.

  STRICT output (raw):
    {"variant": "success", "label": "Active"}
  parsed: {"variant":"success","label":"Active"}

  CONTROL (json_object, same prompt):
    {"badge": {"variant": "success", "label": "Active"}}
  parsed: {"badge":{"variant":"success","label":"Active"}}

--- CHECKS ---
  enum violated by the strict output : YES (variant=success)
  "required" honoured by the output   : NO — missing component
  code fence in the strict output     : no
  trailing prose after the JSON       : no
  control (no schema) chose          : variant=success
  shape: strict=label,variant · control=badge

--- VERDICT ---
  NOT ENFORCED. Without a schema the model answers "success"; with the strict schema it still answers "success" — a value the schema forbids. The schema was in the request and the output ignored it, so this route is NOT constraining the decoder.

  WHAT THIS MEANS FOR THE ARMS:
  The schema reached the model as a SHAPE HINT, not as a constraint.
  The strict output is shaped like the schema (label,variant) while the
  unconstrained output is not (badge) — so the route DID
  use the schema's structure. It did NOT use its constraints:
  - the enum was violated: variant="success", the schema allows only "danger"
  - "required" was violated: the output is missing component
  So json-object vs strict compares two PROMPTS, not two decoders: the
  strict arm's numbers describe a route whose schema was never enforced.
  The requirement metric is unaffected — it scores the tree against the
  spec, not against the schema.

```
